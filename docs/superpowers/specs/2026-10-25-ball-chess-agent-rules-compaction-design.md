# Ball Chess Agent 规则投影与专用压缩设计

- 日期：2026-10-25
- 状态：设计已确认，待实施
- 代码归属：`ball_chess` 仓库
- 依赖：现有共享 Agent Client、DSH Cordis 插件与 `@deepseek-ai/dsh-compaction-basic`

本文扩展已经完成的 Ball Chess 席位、准备、MCP 与 DSH 接入。目标是让人类、MCP Agent 和 DSH Agent 在相同的权威规则与状态语义下完成对局，并为 Ball Chess 预设提供领域专用的自动上下文压缩。本文不改变棋局规则、对局记录格式或 DSH Agent Loop。

## 1. 问题与目标

当前 DSH 插件能够认领席位、准备、等待和提交合法行动，但模型主要依赖工具返回的合法行动列表，并未获得一份完整、动态且可恢复的规则说明。MCP 和 DSH 的结构化结果共享客户端，面向模型的文本投影仍缺少终局原因、墙配额、剩余时间等决策信息。现有 DSH overlay 还通过绝对 `file:` URL 加载插件，无法随项目目录移动。

通用 `compaction-basic` 可以自动处理压力、模型切换和上下文溢出，但其摘要结构面向软件工程任务。Ball Chess 对局需要保留的事实更少、更明确：本局规则、席位、最近观察到的权威版本、棋盘、等待原因、用户要求和终局结果。继续使用通用摘要容易保留无关工程栏目，同时遗漏动态墙配置或把过期版本当作当前状态。

本方案需要同时做到：

- 给 Agent 明确、完整且与本局配置一致的游戏规则与胜利目标。
- 让 DSH、MCP、程序 Agent 和前端从同一个规则及状态描述来源投影内容。
- 保持后端为唯一权威；摘要和客户端不得成为第二套棋局状态。
- 在有限墙和无限墙设置下正确描述双方已使用与剩余墙数，不写死数量。
- 在工具结果中明确当前行动方、版本、超时、合法行动和终局原因。
- 用 Ball Chess 专用压缩插件复用 `compaction-basic` 的生命周期，只替换摘要策略。
- 把 Ball Chess 作为本地 DSH bundle 安装，消除绝对插件路径。
- 在终局工具结果可靠进入当前模型调用前不销毁恢复所需的绑定。

### 1.1 非目标

- 不实现独立策略引擎、搜索算法或保证 Agent 采用最优行动。
- 不让压缩插件访问 Ball Chess 后端或修改对局状态。
- 不把规则全文复制进每次工具返回。
- 不修改 DSH Agent Loop，也不在通用压缩包中加入 Ball Chess 分支。
- 不让 MCP 和 DSH 各自维护一套规则说明或状态格式。
- 不把摘要中的版本、棋盘或墙数提升为权威状态。

## 2. 设计原则

1. **服务器状态是唯一权威。** Agent 的系统提示、工具文本和压缩摘要都是投影；提交行动必须使用最近一次权威工具结果中的版本。
2. **规则由配置派生。** 棋盘尺寸、目标行、先手、最大手数、回合时限和墙配额都来自实际对局配置，不能由客户端常量拼装出另一套解释。
3. **规则与状态分开。** 规则描述回答“本局如何进行”，状态描述回答“现在发生了什么”。静态规则可以复用，动态状态必须随版本变化。
4. **模型文本与程序数据各司其职。** 结构化结果保留完整机器可读字段；文本结果只包含下一次决策所需信息，并可对大量合法墙位做无损压缩。
5. **压缩只替换摘要策略。** 自动触发、区间选择、持久化、模型切换保护、溢出恢复、取消和手动压缩继续由 `BasicCompactionEngine` 负责。
6. **秘密不进入模型历史。** 玩家 token 永不进入规则、状态投影、摘要、Session 日志或普通日志。邀请码在兑换完成后也不进入后续摘要。
7. **错误不会伪装成恢复。** 摘要为空、截断或包含不支持内容时不提交 checkpoint；终局清理失败或结果未知时向拥有者暴露明确状态。

## 3. 共享规则与决策投影

### 3.1 规则描述器

在 Ball Chess 仓库中增加纯函数规则描述器。输入是已经由服务端验证的对局配置以及可选的玩家视角，输出分为：

- 结构化规则描述，供程序客户端和测试断言；
- 简短文本规则，供 DSH persona、MCP 指引和前端规则面板使用。

描述器不读取存储、不访问网络、不判断行动是否合法。它只把引擎已经采用的配置转成统一语义，包括：

- 棋盘为 9 列、13 行，坐标原点位于左下角；
- 左方初始位置 `(2, 0)`，右方初始位置 `(6, 0)`；
- 任一棋子先到达 `y = 12` 获胜；
- 每回合选择一次正交移动或放置一堵覆盖两条边的墙；
- 禁止斜走、跳过或进入对方所在格，也不能跳过回合；
- 墙不得重叠或相交，允许端点连接或 T 形连接，并且双方始终必须保留至少一条通往目标行的路径；
- 实际先手、最大手数、回合时限和墙配额。

墙规则必须按本局 `wallLimit` 派生：

- `wallLimit === null`：描述为无限墙，只显示双方已使用数量；
- 有限整数：显示每方上限、已使用数量和 `max(0, limit - used)` 的剩余数量。

描述器不得采用默认墙数量代替实际配置。前端、MCP 和 DSH 均不再各自拼接这段内容。

### 3.2 决策状态投影

共享 Agent Client 继续返回完整结构化状态，同时由一个纯投影函数生成面向模型的紧凑文本。文本按固定顺序包含：

1. 对局 ID、当前状态和权威版本；
2. 自己的席位、当前行动方以及是否轮到自己；
3. ASCII 棋盘和最近一次行动；
4. 本局墙配置以及双方已使用或剩余数量；
5. 回合截止时间或剩余时间；不限时则明确标为不限时；
6. 当前可执行操作；
7. 恢复提示，例如等待、刷新状态或用当前版本提交行动。

等待阶段额外显示双方席位阶段。进行阶段显示本局规则的紧凑引用，不重复整篇规则。首次加入结果与显式读取状态可以携带完整规则文本，使模型在开始决策前知道目标与限制。

终局投影必须包含：

- `winner`，和棋或中止时允许为空；
- 稳定的 `reason`；
- 最终版本；
- 最终棋盘和最后行动；
- 双方墙使用情况；
- 明确说明不得继续提交行动。

### 3.3 合法行动压缩

结构化结果保留完整合法行动数组。文本投影对规则性较强的墙行动做无损范围压缩，以减少上下文占用；移动行动保持逐项列出。

压缩结果必须满足：

- 每个文本范围可以确定性还原为原始行动集合；
- 不合并中间存在非法位置的范围；
- 水平墙和垂直墙分别编码；
- 顺序固定，输入相同则文本完全相同；
- 测试同时断言压缩前集合和解压后的集合相等。

模型仍可从结构化结果选择具体行动；文本压缩只优化阅读与历史长度，不改变工具 schema。

## 4. DSH bundle 与预设装配

Ball Chess 根项目声明为一个本地可安装的 DSH bundle。bundle patch 位于项目内，并插入 Ball Chess Agent preset。由于 preset 的嵌套插件行不继承 bundle patch 的解析基址，工具插件和专用压缩插件通过 `package.json` 导出的 `ball-chess/dsh/plugin` 与 `ball-chess/dsh/compaction-plugin` 子路径加载；配置中不保存机器相关绝对路径。

安装方式为：

```powershell
dsh plugin --profile web add E:\My_project\ball_chess
```

安装后由 Web profile 的 bundle 列表加载，不再要求启动命令携带绝对 `--patch`，也不在 YAML 中保存 `file:///E:/...`。本地链接使编辑后的插件代码保持可开发性；运行时的 Cordis、LLM 和 compaction 类型由正在运行的 DSH 提供，Ball Chess bundle 不创建第二套 DSH 服务实例。

预设保持最小能力：

- Ball Chess persona；
- Ball Chess 专用 compaction service；
- `join_by_invite`、`set_ready`、`get_match_state`、`wait_for_turn`、`submit_action`；
- 不启用 shell、文件系统、浏览器或任意代码执行工具。

persona 说明完整目标、行动流程和恢复原则，但不写死墙数量。它明确要求所有动态墙信息以工具返回的本局配置为准。

## 5. Ball Chess 专用压缩插件

### 5.1 结构

专用插件导出一个继承 `BasicCompactionEngine` 的 Cordis service，并成为 Ball Chess preset 的唯一 `compaction` provider。它复用父类的：

- 自动压力检测；
- 压缩区间选择与保留尾部；
- durable replacement 与 Session 事件；
- 手动 `/compact`；
- 模型切换前压缩；
- 上下文溢出恢复；
- 取消、重试和工具结果预裁剪。

子类只覆盖 `summarize()`。它通过 DSH 公共 LLM seam 发起一次 `purpose: 'compaction'` 的文本摘要请求，复用待压缩区间原有的 system、tools 和 messages 前缀，以保留 `compaction-basic` 的前缀缓存特性。插件不复制父类的区间、压力或持久化实现。

### 5.2 摘要结构

摘要固定输出以下章节，章节缺少内容时写 `(none)`，不得删除章节：

```text
## Match Identity
## Rules and Configuration
## Last Observed Authoritative State
## User Instructions
## Pending Action
## Outcome
```

各章节语义如下：

- **Match Identity**：对局 ID、自己的席位和非秘密显示身份。
- **Rules and Configuration**：本局实际配置与仍需遵守的规则；墙数量按有限或无限设置描述。
- **Last Observed Authoritative State**：最近一次权威工具结果明确给出的版本、状态、当前玩家、棋盘、最后行动、墙使用和截止时间。
- **User Instructions**：用户仍然有效的明确要求，例如开始、继续或简洁报告结果。
- **Pending Action**：下一步应调用的一个工具以及原因。
- **Outcome**：仅在已经结束时记录 winner、reason 和最终版本。

摘要指令包含以下约束：

- 只采用最近一次权威工具结果作为动态状态来源；较早版本只用于历史，不得覆盖较新版本。
- 无法确认当前版本时写明需要调用 `get_match_state`，不得猜测。
- 对局尚未轮到自己时写明调用 `wait_for_turn`。
- 不把摘要中记录的版本视为永久有效；提交行动前必须以保留尾部或新工具结果确认。
- 已兑换的邀请码不保留；玩家 token 在任何情况下都不得输出。
- 旧 checkpoint 只合并仍然有效的事实，不逐字嵌套。
- 只输出 checkpoint 文本，不调用工具、不评价策略、不继续对局。

### 5.3 默认配置

专用插件沿用 `BasicCompactionConfig` 的部署配置，并在 preset 中给出以下默认值：

```yaml
auto: true
thresholdRatio: 0.8
headroomTokens: 65536
retainTokens: 8192
maxTokens: 4096
compactionRetries: 1
maxOverflowRetries: 1
```

`maxTokens: 4096` 只限制辅助摘要请求，不修改正常对局模型请求的最大输出。正常模型的输出预留仍参与父类压力阈值计算。配置值保留在 YAML 中，不硬编码进插件。

对 1,048,576 上下文、32,768 最大输出的模型，压力阈值由父类按上下文比例、输出预留和 headroom 共同计算。对 262,144 上下文、128,000 最大输出的模型，输出预留会使自动压缩显著提前；专用插件不绕过这一计算。

## 6. 终局交付与凭证生命周期

当前工具插件在看到 `finished` 后立即删除 Session grant 和关闭客户端。若进程在工具执行完成后、工具结果可靠写入 Session 前退出，模型可能没有收到最终结果，而恢复所需绑定已经被删除。

本方案把终局分成两个事实：

1. 后端权威状态已经结束；
2. 当前 DSH Session 已可靠获得可恢复的终局回执。

工具执行看到终局时先返回完整终局投影，并保留一个不含玩家 token 的终局引用。长期玩家 token 的清理由一个可验证的提交点触发：只有终局工具结果已经进入 Session 日志，或者下一次恢复读取确认后端仍为同一终局，才删除 token 并关闭该 Session 的活动客户端。清理必须幂等；重复观察终局不会产生不同结果。

如果持久凭证清理失败，已经结束的对局仍不得重新接受行动。插件报告清理失败但保留可重试记录，不能把“删除失败”伪装为对局失败，也不能重新生成席位绑定。

## 7. 前端规则展示

等待和进行阶段增加简短规则面板，内容来自共享规则描述器：目标、移动方式、墙约束、先手、最大手数、时限和本局墙配置。有限墙显示上限及双方剩余数量；无限墙明确显示“无限”，不渲染伪造的剩余值。

规则面板不负责判定合法性，不复制引擎逻辑。前端继续以服务端状态、合法行动和错误码决定可操作状态。终局页面显示 winner、reason、最终版本和双方墙使用情况，与 Agent 终局投影使用相同字段。

## 8. 错误处理

### 8.1 压缩错误

摘要请求出现以下情况时拒绝提交 checkpoint：

- LLM 返回 error 或 aborted finish；
- 达到摘要 token 上限而截断；
- 输出包含图片或其他非文本内容；
- 文本为空；
- 固定章节无法解析或缺失；
- provider/model 无法解析。

自动压力压缩失败时沿用父类行为：记录警告并继续当前 turn。模型切换所必需的压缩失败时拒绝切换并保留旧模型。上下文溢出恢复只使用父类有限重试预算；已经落地的无模型工具结果裁剪可以作为有效进展，但不得把后续摘要失败描述为完整成功。

### 8.2 投影错误

规则描述器接收的配置已经由后端验证。面向网络、磁盘和工具 JSON 的输入仍在现有边界验证。未知终局原因、缺失版本或结构不一致不能被文本渲染器静默默认；调用方应停止依赖该投影，并返回稳定错误及重新读取状态的动作。

合法行动文本压缩若无法证明无损，则退回逐项文本输出；结构化数组始终保持原值。

## 9. 测试与验收

### 9.1 纯函数与单元测试

- 完整规则描述覆盖移动、胜利、墙约束、先手、最大手数和时限。
- `wallLimit: null` 显示无限墙及双方 used，不出现 remaining。
- 有限墙显示 limit、used、remaining，且剩余值与实际配置一致。
- 合法墙行动压缩可确定性解压为原集合；空洞范围、方向和排序正确。
- 进行中、等待中、轮到自己、轮到对手和终局文本包含所需字段。
- 终局文本包含 winner、reason、最终版本和停止行动提示。
- 所有模型可见输出均不包含 player token。

### 9.2 压缩插件测试

- 通过真实 Cordis Loader 组合加载专用 compaction service，而不是只手工实例化类。
- 压缩请求保留原 system/tools/messages 前缀，末尾追加 Ball Chess 摘要指令。
- 摘要模型目标、`purpose`、`maxTokens`、Session ID 和取消信号正确传递。
- 正常摘要生成固定六节 checkpoint。
- 已兑换邀请码和 player token 不出现在 checkpoint。
- 有限墙和无限墙摘要均取最近权威结果，不采用固定数量。
- 旧版本与新版本同时出现时只把新版本标为最近观察状态。
- 截断、空文本、非文本输出和模型错误不会提交 replacement。
- 自动压力、手动 `/compact`、模型切换和上下文溢出仍由基础引擎按原语义工作。

### 9.3 生命周期与恢复测试

- 终局工具结果写入前的模拟进程中断不会丢失恢复绑定。
- 工具结果已记录后清理 token，重复清理幂等。
- 清理失败保留可重试记录，且对局仍保持 finished。
- 冷恢复后能重新取得相同终局并完成清理。
- fork 和 subagent 仍不继承席位绑定。

### 9.4 产品组合与端到端测试

- 用 `dsh plugin --profile web add <ball_chess>` 安装本地 bundle，`--dump-config` 显示 preset、工具和专用压缩插件。
- 从不同当前工作目录启动 Web profile，配置中不存在机器专属绝对插件路径。
- MCP 和 DSH 对相同状态生成等价的规则、墙信息、版本与终局字段。
- 两个 DSH Session 使用邀请码认领不同席位、ready、轮流行动并完成一局。
- Agent 与人类共用 ready 与行动状态机完成一局。
- 长对局触发自动压缩后，Agent 重新读取权威状态并继续，直至终局。
- 前端规则面板在有限墙、无限墙、有限时和不限时设置下与后端一致。

模型或产品用户可见文本变化需要更新可审阅 snapshot。端到端测试验证真实 bundle/profile/Loader 入口；单元测试不替代实际装配验证。

## 10. 实施边界与顺序

实施按以下依赖顺序进行：

1. 提取共享规则描述器和决策投影，补齐结构化状态字段。
2. 接入 MCP、DSH 和前端，加入动态墙描述与合法行动文本压缩。
3. 修复终局回执与凭证清理顺序。
4. 把 Ball Chess 根项目声明为 DSH bundle，移除绝对路径 overlay。
5. 实现并装配 Ball Chess 专用 compaction service。
6. 增加 snapshot、真实 Loader 组合与端到端覆盖。

每一步都保持后端权威语义不变。共享投影先完成，避免专用压缩提示建立在随后还会变化的模型文本上。

## 11. 完成判定

以下条件全部满足时，本方案实现完成：

1. Agent 在开始对局前能获得完整规则、胜利目标和本局动态配置。
2. 有限墙与无限墙在前端、MCP、DSH 和压缩摘要中一致，没有固定数量假设。
3. 所有行动继续由服务端验证，摘要中的旧状态不能直接授权提交。
4. DSH preset 使用 Ball Chess 专用 compaction service，并保留基础引擎的自动、手动、模型切换和溢出恢复行为。
5. 压缩摘要不包含玩家 token 或已兑换邀请码，失败摘要不会落地。
6. 终局结果在绑定清理前可靠交付并可在中断后恢复。
7. Ball Chess 通过本地 bundle 安装到 Web profile，配置不包含机器专属绝对插件路径。
8. MCP 与 DSH 的模型可见投影通过共享 snapshot 保持一致。
9. 两个 Agent 经过至少一次压缩后仍能从邀请码开始并完成整场对局。

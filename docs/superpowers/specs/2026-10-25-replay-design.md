# 已结束对局重播设计

日期：2026-10-25

## 目标与范围

在现有 Ball Chess 页面中为已结束对局提供重播。玩家与观战者均可使用，无需席位令牌，不重新运行 Agent。

首版仅支持已结束对局，包括获胜、和棋、回合超时、无合法行动和管理员中止。进行中对局不提供重播入口。

## 方案

浏览器读取现有 `GET /api/matches/:id/record` 返回的脱敏棋谱，复用 `core/state.js` 的 `createGame` 和 `core/engine.js` 的 `applyAction` 重建局面。现有 SVG 棋盘负责渲染。

不新增后端接口，不修改对局规则、MCP、持久化格式或前端依赖。

## 组件与数据流

### API

在 `MatchApi` 中增加 `record(id)`，调用现有 `/api/matches/:id/record`。该请求不发送玩家或管理员令牌。

### 重播模块

新增独立浏览器纯模块，输入公开棋谱和当前最终快照中的席位信息，执行完整棋谱并返回有序快照数组及行动记录。

第 0 手是 `createGame(record.config)` 的初始局面。第 N 手是依次应用前 N 条 `record.actions` 后的局面。每个快照包含棋盘渲染所需的 `players`、`walls`、`currentPlayer`、`plies`、`lastAction`、`config` 和 `seats`。

进入重播前重建并校验完整棋谱，避免展示半段不可靠重播。每条行动必须由记录中的行动方在对应回合合法执行，且引擎不得在末手之前产生终局。若引擎在末手产生终局，其 `kind`、`winner` 和 `reason` 必须与 `record.result` 一致；若引擎没有产生终局，则只接受 `turn_timeout` 或 `admin_abort` 作为记录终局原因。其他缺失或不一致的终局都会被拒绝。中间快照不显示终局；校验通过后，末快照采用 `record.result`，从而保留回合超时和管理员中止等无法仅由 `applyAction` 重现的终局原因。

### 页面状态

实时最终快照与重播状态分开保存。重播状态至少包含对局 ID、快照数组、当前索引和播放计时器。实时快照不被重播修改，“返回终局”直接恢复最新最终快照。

所有异步回调都核对当前对局 ID 和最近一次加载请求标识，避免同一对局重复进入时旧响应覆盖新状态。切换对局、退出重播及页面卸载时清理计时器，并忽略迟到响应。重播进度和播放状态不写入 `localStorage`；刷新只恢复最终对局，需重新点击进入重播。

## 交互与显示

已结束对局显示“观看重播”。点击进入后：

- 从第 0 手开始，初始为暂停状态，不自动播放。
- 隐藏移动和放墙控件，棋盘不注册行动交互。
- 显示重播工具栏：回到开头、上一步、播放/暂停、下一步、进度滑块和返回终局。
- 状态文字为“重播 · 当前手数/总手数”。第 0 手行动说明为“初始局面”，其余显示手数、行动方及移动或放墙详情。
- 棋盘、双方剩余墙数和行动记录随进度更新；行动记录仅包含当前手数及之前的最近八条。
- 只有末快照显示终局结果。

播放速度固定为每 800 ms 一手。播放到末手自动停止。回到开头、上一步、下一步及拖动滑块都会暂停；播放按钮在末手变为“重新播放”，从第 0 手开始播放。首末位置的边界按钮正确禁用。总手数为 0 时只显示唯一的末快照，播放、上一步和下一步均禁用。

重播控件沿用现有现代哑光视觉风格，在窄屏下换行且保持可用。页面本就只在用户明确点击后播放，不增加自动动画。

## 异常处理

棋谱请求失败时停留在最终局面并显示错误。棋谱重建或校验失败时同样不进入重播。

重播期间不提交行动，不调用 `join`、`setup` 或管理接口，不改变服务器状态。

## 验证

### 自动化测试

- API 的 `record` 地址、无令牌请求和错误传播。
- 第 0 手、移动、放墙、任意索引、末手和空棋谱。
- 非法行动、错误顺序及不完整棋谱会拒绝重播。
- 回合超时和管理员中止在末快照保留原终局原因。
- 播放、暂停、逐步、拖动、末手停止及重新播放。
- 重播棋盘无可执行行动，退出后恢复原最终快照。

### 浏览器验收

使用本机 Chrome 和已完成的 38 手对局 `m_ZNztIOSIv_by` 验证：进入重播、初始位置、逐手移动、墙体出现、拖动、播放暂停、末手获胜、返回终局、刷新恢复及窄屏布局。

运行完整现有测试及新增测试、JavaScript 语法检查和 `git diff --check`。验收服务在结束时清理，不保留临时进程。
